## Deliberate authorization changes

- **Role to relationship authorization:** the new owner helpers use `owner_id` and stored relationships. Role-based policies and the old scoped admin-profile policy are removed; profile self-select and self-update remain.
- **Existing attempt helper:** `private.owns_attempt(uuid)` from migration 0005 already has `search_path = ''`, no role reference, and compares stored `student_id` to `auth.uid()`; no change needed.
- **Group-only exam access:** direct `exam_permissions.student_id` access is eliminated. Current membership in a group permission owned by the exam owner is required. The approved separate cleanup removed the single legacy row; migration preflight remains fail-fast and does not delete data.
- **Membership creation:** direct client `group_students` INSERT/UPDATE is removed. Invitation redemption is the sole client creation path; owner-only direct DELETE remains.
- **Attempt identity:** the four attempt RPCs no longer accept `p_student_id`; identity comes from the caller JWT and the stored attempt. Question projection does not return correct answers.
- **Result visibility:** the attempt participant retains access, and the exam owner gains the approved result path. Student-role membership no longer decides access.
- **Signature retirement:** old student-id attempt overloads and old permission/member/email-list RPC names are explicitly revoked and dropped; the new permission-list RPC has an explicit replacement name.
- **Internal maintenance:** cron/trigger functions remain callable through their database-owned invocation paths. Their EXECUTE privilege is removed from client and service roles; cron jobs continue running as postgres.
- **Least privilege:** the three reviewed tables lose broad client grants. `exam_attempts.access_token` is excluded from authenticated SELECT and anon receives no table or column privilege. Service-role grants retained for fixture setup/cleanup are technical debt, not production runtime requirements evidenced in the reviewed callers.
