# 0017 / T027 / T028 Test Impact Inventory

Read-only inventory of `tests/` and `supabase/tests/` against the 0017 mapping, T027 membership-invitation change, and T028 JWT-forwarding change. No tests were run. Actions below are recommendations; this inventory does not edit test code.

## Contract used for classification

- 0017 replaces the four attempt RPC signatures that take caller-supplied `p_student_id` (the old three/six-argument forms) with caller-JWT identity. The old `list_exam_permissions`, `list_group_students`, and `search_student_by_email` RPCs are retired. T027 replaces direct email lookup/add with invitation redemption and group-only exam permissions. T028 forwards the caller JWT to the new attempt RPCs.
- Authenticated users may read only the approved safe `exam_attempts` columns; `access_token` is excluded and `select=*` must fail for authenticated users. Anon has no attempt table access. Authenticated/anon direct attempt writes are revoked.
- Authenticated `group_students` INSERT/UPDATE is revoked; owner DELETE remains. Authenticated/service-role `exam_permissions` writes are group-only (`exam_id`, `group_id`); `student_id` is prohibited. Service-role fixture privileges are explicitly column-scoped. Internal cron/trigger functions, including `fn_sweep_expired_attempts`, are not directly executable by service-role or client roles.
- `expected-transition` means preserve a before-state baseline as evidence; do not rewrite frozen before tests (especially anything under `security-baseline/before/`).

## Client-role and service-role findings

- No direct `exam_attempts` INSERT/UPDATE by authenticated or anon test clients was found. Direct attempt fixture inserts in the active unit/visual suites use `adminClient`/service-role. Service-role attempt INSERT is explicitly granted for fixture setup, but `fn_sweep_expired_attempts` EXECUTE is revoked, so the direct RPC tests need the update above.
- Authenticated safe-column attempt reads exist in `tests/unit/db/results-rls.test.ts:25-37`. The broad default `select=*` attempt probes are in the frozen `rls-before` suite (`request` default at lines 21-22 and attempt reads 121-129). No active post-cutover test explicitly checks denial of `access_token` or `select=*` for both authenticated and anon.
- Direct `group_students` client INSERT denial is already asserted in `tests/unit/services/group-invitation-redemption.test.ts:52-56` and after-state SQL `cutover-0017.sql:25-43`; before-state owner INSERT/UPDATE allows are in `rls-before.test.ts:71-77` and must remain historical. Service-role membership fixture INSERTs are explicitly granted.
- Direct individual `exam_permissions` writes occur in `tests/unit/services/exam-publish.test.ts:43-46`, `tests/visual/student-exam-submit.spec.ts:66-71`, `tests/visual/student-exam-offline.spec.ts:76-81`, and the authenticated negative probe `tests/unit/services/privilege-escalation.test.ts:65-70`. The first three use service-role but still violate the new `student_id`-free constraint; the negative probe needs a valid group-only row to test authorization rather than row validity.
- Before-state role/policy assertions are confined to the `*-before` security suites and SQL listed above. Active test-context helpers still set `profiles.role` via service-role for product/UI fixture roles; that is not itself a role-gate assertion. Keep these fixtures distinct from tests claiming that `is_admin`/`is_student` authorizes data access.

## T031 gaps that need new after-state tests

`PermissionTarget` has no hits in tests. The old `revokeExamPermission(examId, { studentId | groupId })` shape appears only in `tests/unit/services/exam-permissions.test.ts:54,113,133-134`; update it to the group-ID contract.

1. **Signup after EXECUTE revoke:** create a new auth user after `fn_create_profile_on_signup()` EXECUTE is revoked; assert the signup trigger still creates the linked profile with the safe default role.
2. **Attempt column boundary:** as authenticated participant, assert approved safe-column SELECT succeeds while explicit `access_token` and `select=*` are denied; as anon, assert safe SELECT and `select=*` are denied. Include owner safe-column allow and unrelated-owner deny.
3. **Post-cutover cron success:** observe `cron.job_run_details` for a successful scheduled run after cutover; do not directly invoke `fn_sweep_expired_attempts` as service-role.
4. **INSERT-only permission upsert:** as the exam owner, INSERT a group permission on `(exam_id, group_id)` with `ON CONFLICT DO NOTHING`; verify duplicate is harmless without requiring an UPDATE privilege/policy path, and a non-owner cannot insert.
5. **Self-promotion probe:** repeat the T024 profile-role self-promotion attempt after cutover, then verify no access to another owner’s groups/exams, associated participant lookup, invitation status/management, attempts, or results. `cutover-0017.sql:82-125` covers only a subset and is not the complete T031 matrix.
6. **Invitation redemption across roles:** redeem an invitation as a user who owns an exam elsewhere but does not own the invited group; assert successful redemption. This distinguishes the removed student-role gate from the still-valid invited-group-owner denial.
